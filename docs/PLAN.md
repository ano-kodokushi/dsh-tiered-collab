# 执行计划书 · PLAN

> 把任务书拆成 Agent 能一口吃掉的小块。
> 粒度铁律：**一个任务要能在一次会话内完成并验证**。做不完说明还能再拆。

## 0. 拆分原则

1. 单个任务改动文件 ≤ 3 个
2. 每个任务必须有明确的验收命令
3. 依赖关系写成 DAG，不允许循环依赖
4. 先骨架后填肉：格式 → 统计 → 编排 → 升档
5. 每个任务都能独立验证

## 5. 单任务执行循环

```
1. 领任务  → 从 BOARD.md 认领
2. 读约束  → 重读 AGENTS.md 第 2 节环境约束 + 第 6 节红线 + 本任务的验收方式
3. 做      → 小步改，每步可运行
4. 验      → 先跑硬验收命令，逐条记录实际输出（不许口头声称完成）
5. 收      → 更新 BOARD.md 状态
```

任一步失败超过 2 次 → 停止，写阻塞记录，不硬扛。

## 6. 状态定义

| 状态 | 含义 |
|---|---|
| 待办 | 还没开始 |
| 进行中 | 已被认领（同时只允许一个） |
| 待审 | 自测通过，等待 verifier |
| 完成 | 硬验收通过且 verifier 判 pass |
| 阻塞 | 卡住，必须写明原因与已尝试的方案 |
